# バランス調整の意図と補足

この文書は、目指すプレイ体験と、バランスに関する判断理由を記録する。

設定値の正本は `data/balance/` の `.tres`、実装仕様の正本はコードとテストとする。ここでは、判断に必要な理由や背景を補足する。検討案や仮説の記載は、数値変更や受入条件変更の承認を意味しない。

## 概要

Vampire Survivors はとても面白いゲームだが、個人的に以下の不満点を感じた。
- 1方向に移動するだけで敵をある程度避けられる
- 20 ~ 28 分の間、無双は出来て楽しいけど暇だなと感じる時間帯があった。

このゲームは上記の不満点を改善するために
- アリーナ形式の採用
- 通常戦20分と、1〜2分を目安とした最終ボス戦
- 難易度曲線の再設計

を行うプロジェクトである。

## 全体で目指す体験

- 目指す遊び心地：敵の状況に応じて移動方向を考えながら、強くなって敵を倒す爽快感も味わえる。
- 調整で守りたい特徴：大量の敵を倒すことで無双できる楽しさ。自分の成長を実感できること。強くなった実感とカタルシスを十分に味わえる時間を確保する。
- 避けたい体験：一方向に移動し続けるだけで安定して生き残れること。敵を圧倒する体験が長く続き、次の展開を待つだけの時間に感じられること。

## 個別の方針と理由

### 難易度曲線

戦闘時間20:00に最終ボスが出現し、撃破でクリアする。ポーズ・レベルアップ選択・宝箱の報酬中は戦闘時間を進めない。
20分は待ち時間を足して作るのではなく、成長と敵編成の変化を配分するための長さとする。

| 時間帯 | 主な体験 | 宝箱の機会 |
|---|---|---|
| 0〜2分 | 操作への習熟と初期成長 | 2分：通常 |
| 2〜8分 | ビルド選択と進化条件の準備 | 4・6分：通常 |
| 8〜12分 | 初進化と、その火力での大量撃破 | 8・10分：進化可能 |
| 12〜16分 | 追加進化と敵編成の複合化 | 12・14分：進化可能 |
| 16〜20分 | ビルド完成と最後の難所 | 16・18分：進化可能 |

2分以降は偶数分からエリートを含む難所、続く1分を大量撃破の時間とする。後半は敵の編成と横断群れの頻度で圧力を増す。
難所では位置取りを考え、次の区間では成長した火力を発揮できるようにする。包囲イベントは追加しない。
難易度の目標は数回の挑戦でクリアを狙えることとし、一方向への移動だけで安定する状態を避ける。

### 成長と宝箱

武器5枠・パッシブ5枠・進化最大4回を使う。初進化の目標は7〜9分とし、最初の進化機会を8分のエリートの宝箱に置く。
通常強化の完了は16〜18分を目安として観測する。選択と回収が噛み合ったランの早期完成は許す。
必要経験値と9回の宝箱で成長を配分し、宝箱の種類と装備条件によって進化を判定する。別の経過時間制限は設けない。

通常宝箱は所持装備の1段階強化、強化先がなければ全回復とする。進化条件を満たしていても進化しない。
進化可能宝箱は進化候補があれば必ず1つ進化させる。候補が複数なら既存の抽選を使い、候補なし・上限到達時は通常強化、強化先もなければ全回復とする。
種類をエリートの出現予定に固定するのは、撃破を遅らせて通常箱を進化箱に変える操作を避けつつ、進化箱を床に残して準備する判断を残すためである。
地面では色と形、報酬画面では名称で区別する。レベルアップ優先・箱の取得順・報酬の一度だけの適用を守る。

### 横断群れ

予告時点で位置と進行方向を固定し、予告終了後はそのまま直進する。移動先を予告から判断できるようにし、プレイヤーの移動に合わせた追尾は行わない。
群れは十分な火力で穴を開けられるHPを持ち、通常敵を押す作用も残す。壁際でも予告の帯の外へ移れる余地を確保する。
予告中・群れの生存中は追加予定を消費して見送り、通過後にまとめて出さない。複数方向が重なって避け場を失う状況を防ぐためである。
群れのHPと接触ダメージ倍率は通常敵の区間倍率から独立させ、大量撃破の区間でも移動判断を保てるようにする。
ボス出現時は通常敵・群れ・未完了の予告を整理し、ボスの攻撃に集中できる状態へ移る。

### 調整と観測

構造と検証を先に整え、人間のテストへ渡す直前に数値を一度だけまとめて調整する。調整後に目標未達でも自動で反復調整せず、測定結果を判断材料として示す。
初進化・全進化の時刻・通常強化完了時刻と未到達件数を記録する。通常強化完了の16〜18分は観測目安で、早期完成を失敗にはしない。
ボットの判断、DPS比率、到達率・クリア率の閾値は維持する。自動測定をゲームの開始条件や人間による成功判定の代わりにはしない。
最終調整完了のユーザー明示後に、通常のGDScriptテストを通し、Godot標準exportで配布物を生成する。人間による成功基準は5人以上×各3runの回答の70%以上が「また遊びたい」とする。

### フィールドの大きさ

32×32mのアリーナを使い、敵の密度と移動判断を両立する。横断群れはアリーナ外からも予告した直線を保って通過し、通常敵への押し出しはアリーナ内に収める。
